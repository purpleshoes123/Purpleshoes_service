# 유지보수 인수인계 체크리스트

기준일: 2026-10-31. 이 문서는 계정·비밀값 전달 파일이 아니라 확인할 대상과 절차입니다. 담당자·초대 결과·확인 날짜는 회사의 비공개 기록에 작성합니다.

## 접근 권한

| 대상             | 확인할 일                                                           |
| ---------------- | ------------------------------------------------------------------- |
| GitHub           | 저장소 초대·PR·리뷰·Actions. main 쓰기 권한은 운영 배포 권한        |
| AWS              | 회사 운영 계정의 지정 역할·SSO, CloudWatch·ASG·ALB·S3·SSM 최소 권한 |
| Shopify          | 운영/개발 스토어, 테마·앱·상품·주문·고객 관리 역할. 개인 계정 초대  |
| 앱 개발          | 기존 bta-proxy 앱·확장 관리 범위, 현재 활성 앱 버전                 |
| 메일·측정        | 사용하는 메일 제공자·Klaviyo·Google·Meta 관리 담당과 권한           |
| 도메인·DNS       | 회사 소유 계정·갱신 담당·인증서·현재 라우팅                         |
| 모바일 별도 자료 | 레포 밖 원본·서명키·인계 자료 담당자. 웹 레포에 복사하지 않음       |

개인 CLI 캐시·전체 `.env`·키 파일을 이메일·PR·공개 레포로 전달하지 않습니다. 회사가 승인한 비밀정보 전달 경로를 사용합니다.

## 배포 연결 확인

- [ ] 기본 브랜치와 최근 Production 성공 실행
- [ ] PR에서는 verify만 실행되고 운영 인증·배포는 실행되지 않는지 확인
- [ ] CI/CD 문서의 Actions 변수·Secrets 이름 확인
- [ ] AWS OIDC의 해당 저장소·main 고유 식별자 제한 확인
- [ ] 실제 ASG 숫자 시작 버전·정상 서버·ALB 상태 확인
- [ ] 비공개 S3 배포 기준과 실제 코드 일치 확인
- [ ] 현재 live 테마와 Actions 대상 일치 확인
- [ ] 과거 저장소의 Shopify 직접 동기화가 다시 연결되지 않았는지 확인
- [ ] 메일 활성 게이트와 실제 작업자 자식 프로세스 확인

## 인증 수명

- 앱 배포 서비스 계정의 확인된 만료일은 **2027-01-30**입니다. 인계 시 재확인하고 교체 담당·기한을 정합니다.
- Theme Access 전달 링크의 유효기간과 실제 테마 인증값의 효력을 구분합니다.
- GitHub Secrets는 값을 다시 읽어 꺼내는 방식으로 인계하지 않습니다. 필요한 경우 발급처에서 승인된 재발급·교체를 수행합니다.
- 새 인증 등록·기능 확인 후 이전 인증을 폐기합니다. 유일한 작동 인증부터 폐기하지 않습니다.
- 위 항목은 절차이며 문서 작성만으로 인증을 재발급·폐기한 것은 아닙니다.

## 첫 기능 확인

- [ ] 비회원: 가이드·투어 소개, 가격·예약 정보 비공개, 로그인 연결
- [ ] 미구매 회원: 검증된 가격·쿠폰·구매 CTA
- [ ] 구매 회원: 권한·기간·Extend Access
- [ ] 투어: 상품·날짜·인원·예약 요약
- [ ] 관리자: 상품 저장·게시, 예약, 권한·쿠폰·리뷰·메일
- [ ] PDF·동영상: 전환·재생·서명 URL 만료
- [ ] 지정 테스트 주소의 무료 신청·구독 동의·구매 메일
- [ ] 환불·취소 후속 처리와 결제사 검증 범위 구분

실제 결제·환불·메일·고객 데이터 변경은 대상과 범위를 정해 수행합니다. 테스트 ID와 정리 결과를 기록합니다.

## 알려진 한계

- Theme Check에는 기존 번역 등의 오류가 남아 있습니다. CI는 새 오류 증가를 차단합니다.
- 마지막 확인에서는 치명적 의존성 항목 0건, 높은 수준 경고 7건 등이 남았습니다. 최신 audit로 재확인하고 별도 호환성 검토합니다.
- 현재 연결 계정은 GitHub 관리자 권한이 없어 main 보호 규칙·관리자용 Secret Scanning 경고 목록까지 확인 완료로 간주하지 않습니다.
- 최초 연결 때 앱 확장 4개 컴파일·전용 인증은 확인했지만 소스 변경이 없어 새 운영 앱 버전 릴리스는 실행되지 않았습니다.

## 인계 완료

새 담당자가 본인 계정으로 PR 검증을 통과시키고 승인된 변경의 배포 결과·복구 자료를 찾아 설명할 수 있어야 합니다. 접근 권한·인증 갱신 담당·장애 연락 경로·미해결 사항을 비공개 기록에 남깁니다.
